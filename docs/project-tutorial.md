# 项目教学文档
# Project Tutorial

这份文档面向第一次接触 `stern-kingdee` 的同事，目标是用最短时间说明这个项目能做什么、不能做什么、应该从哪里开始看，以及 `workspace/` 里的业务脚本和根目录公共能力之间是什么关系。
This document is for teammates who are new to `stern-kingdee`, and its goal is to explain as quickly as possible what this project does, what it does not do, where to start reading, and how the business scripts under `workspace/` relate to the shared capabilities in the repository root.

## 1. 先用一句话理解项目
## 1. Understand the Project in One Sentence

这个项目是一个基于 Python 的金蝶云星空只读集成工具。
This project is a Python-based read-only integration tool for Kingdee K3 Cloud.

它的核心职责不是搭系统页面，而是提供两层能力。
Its core responsibility is not to build application pages, but to provide two layers of capabilities.

1. 根目录公共层：封装金蝶官方 Python SDK，支持检查配置、查询数据、查看单据、读取字段元数据。
1. Shared root layer: wraps the official Kingdee Python SDK and supports configuration checks, data queries, record viewing, and field metadata inspection.
2. `workspace/` 业务层：在公共能力之上，针对某个具体业务场景写专项脚本，例如读取 Test Plan、比对金蝶主数据、生成导入 Excel。
2. `workspace/` business layer: builds scenario-specific scripts on top of the shared capabilities, such as reading a Test Plan, comparing it with Kingdee master data, and generating import Excel files.

如果把它类比成分层结构，可以这样理解。
If you think of it as a layered structure, you can understand it like this.

- `src/` + `main.py` = 通用连接器和命令行工具
- `src/` + `main.py` = shared connector and command-line tool
- `workspace/某个目录/` = 某个业务需求的落地脚本和产物
- `workspace/a-directory/` = implementation scripts and outputs for a specific business requirement

## 2. What This Project Is Good For

- Verifying locally that the Kingdee SDK is available

当前仓库明确是“只读集成 + 本地数据加工工具”，不是完整 ERP 扩展平台。
This repository is explicitly a “read-only integration + local data processing tool”, not a full ERP extension platform.

## 5. 配置文件怎么分工
## 5. How the Configuration Files Are Split

这个项目故意把配置拆成了两类。
This project intentionally splits configuration into two categories.

### `conf.ini`
### `conf.ini`

这个文件放敏感配置，主要是金蝶 SDK 登录信息，例如：
This file stores sensitive configuration, mainly the Kingdee SDK login information, such as:

- `X-KDApi-AcctID`、`X-KDApi-UserName`、`X-KDApi-AppID`、`X-KDApi-AppSec`、`X-KDApi-ServerUrl`
- `X-KDApi-AcctID`, `X-KDApi-UserName`, `X-KDApi-AppID`, `X-KDApi-AppSec`, and `X-KDApi-ServerUrl`

这个文件不应该提交到仓库。
This file should not be committed to the repository.

### `.env`
### `.env`

这个文件放非敏感运行参数，例如：
This file stores non-sensitive runtime parameters, such as:

- 读取哪个 `conf.ini`
- Which `conf.ini` file to read
- 用哪个节名
- Which section name to use
- 查询 JSON 参数
- Query JSON parameters
- `View` 的 `FormId` 和参数
- The `FormId` and parameters for `View`
- 可选的 SDK wheel 路径
- An optional SDK wheel path

你可以把它理解成：
You can think of it like this:

- `conf.ini` 决定“怎么连金蝶”
- `conf.ini` decides “how to connect to Kingdee”
- `.env` 决定“这次要查什么、怎么看”
- `.env` decides “what to query this time and how to query it”

## 6. 第一次上手应该怎么做
## 6. How to Get Started the First Time

建议按这个顺序，不要一上来就跑业务脚本：
Follow this order, and do not start by running business scripts directly:

1. 建虚拟环境并安装依赖
1. Create a virtual environment and install dependencies
2. 复制 `.env.example` 为 `.env`
2. Copy `.env.example` to `.env`
3. 复制 `conf.ini.example` 为 `conf.ini`
3. Copy `conf.ini.example` to `conf.ini`
4. 默认直接使用仓库自带的 SDK wheel；如果要切换版本，再在 `.env` 里指定其他路径
4. Use the SDK wheel bundled with the repository by default; if you need a different version, point `.env` to another path
5. 先执行 `python main.py check`
5. Run `python main.py check` first
6. 确认公共层没问题后，再执行具体 `workspace` 里的业务脚本
6. Only after the shared layer works correctly should you run the business scripts inside `workspace`

示例命令：
Example commands:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
copy conf.ini.example conf.ini
python main.py check
```

默认情况下不需要你手动再拷贝 wheel，因为仓库已经包含 `.vendor/kingdee.cdp.webapi.sdk-8.2.0-py3-none-any.whl`。
By default, you do not need to copy another wheel manually, because the repository already includes `.vendor/kingdee.cdp.webapi.sdk-8.2.0-py3-none-any.whl`.

如果 `check` 都没过，不要直接排查业务脚本，先把 SDK 和配置问题解决。
If `check` does not pass, do not debug business scripts first; solve the SDK and configuration issues first.
